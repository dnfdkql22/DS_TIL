# ML 모델 - Decision Tree (의사결정나무)

## 1. Decision Tree (의사결정나무)

- 특정 기준(질문)에 따라 데이터를 구분하는 모델
- 한 번의 분기 때마다 변수 영역을 두 개의 하위 영역으로 구분하는 재귀적 이진 분할 방식 사용
- 분할 기준에 따라 데이터를 반복적으로 나누고, 최종적으로 리프 노드(Leaf Node)에서 예측 결과 산출

### 1) Node 분할

- 엔트로피(Entropy) : 데이터 세트의 불확실성 또는 무질서도를 측정
- 정보이득(Information Gain) : 특성이 데이터를 분할했을 때 엔트로피를 얼마나 감소시키는지를 나타냄
- 정보이득이 큰 방향으로 노드 분할

#### 엔트로피(Entropy)

- 데이터의 불확실성을 측정하는 지표
- 엔트로피 값이 클수록 데이터가 혼합되어 불확실성이 높음
- 엔트로피 값이 낮을수록 데이터가 특정 클래스에 집중되어 순수도가 높음
- 모든 데이터가 하나의 클래스에 속하면 엔트로피는 0

#### 정보이득(Information Gain)

- 노드를 분할한 후 데이터의 엔트로피가 얼마나 감소하는지를 나타내는 지표
- 정보이득이 클수록 분할 후 데이터의 불확실성이 감소하고, 데이터의 순수도가 높아짐
- 정보이득이 큰 특성은 더 유용한 정보를 제공한다고 판단하여 분할 기준으로 선택

---

## 2. Decision Tree - Classification (분류)

- 데이터를 특정 기준에 따라 분할하여 각 데이터가 어느 클래스에 속하는지 예측하는 모델
- 분할을 통해 각 하위 노드의 클래스 불순도를 감소시키는 방향으로 학습

### 분할 기준

- 하위 노드 내 클래스의 불순도(Impurity)를 줄이는 방향으로 분할
- 대표적인 분할 기준
  - Gini Impurity (지니 불순도)
  - Entropy (엔트로피)
- 목표 : 클래스 레이블이 동일한 데이터가 한 그룹에 모이도록 분할

### Leaf Node Prediction (리프 노드 예측)

- 해당 리프 노드에 도달한 훈련 데이터 중 가장 많은 클래스를 최종 예측값으로 선정
- 다수결 방식으로 클래스 결정

### Example

- 이메일 스팸 분류
  - 이메일의 단어, 발신자, 첨부파일 등의 특징을 기반으로 스팸 여부 예측
- 고객 이탈 여부 예측
- 대출 승인 여부 예측

---

## 3. Decision Tree - Regression (회귀)

- 데이터를 조건에 따라 분할하고, 각 리프 노드에 모인 데이터의 평균값 또는 중앙값을 예측값으로 사용하는 모델
- 연속적인 수치형 값을 예측

### 1) 회귀 트리의 분할 기준

- 각 하위 그룹 내부의 평균 제곱 오차(MSE)를 최소화하는 방향으로 데이터를 분할
- 비슷한 정답값을 가진 데이터들이 같은 그룹에 모이도록 분할
- 각 노드에서 대상 변수의 분산 또는 MSE를 감소시키는 방향으로 분할

### 2) 단일 트리의 예측

- 질문(분기)을 따라 내려가 마지막 끝점인 리프 노드에 도착
- 해당 리프 노드에 속한 훈련 데이터의 대상값 평균을 계산
- 계산된 평균값을 최종 예측 결과로 출력

### 3) 랜덤 포레스트 회귀 예측

- 서로 조금씩 다르게 학습한 여러 회귀 트리가 각각 예측값 산출
- 개별 트리의 예측값을 모두 더한 후 평균 계산
- 여러 트리의 예측 결과를 결합하여 개별 트리의 예측 오차를 완화
- 최종 평균값을 예측 결과로 사용

---

## 4. Decision Tree - Classification과 Regression의 공통점 및 차이점

### 공통점

#### 1) Tree Structure (트리 구조)

- 각 노드가 속성에 대한 테스트 또는 분할 기준을 나타냄
- 각 분기가 테스트 결과를 나타냄
- 최종적으로 예측 결과를 나타내는 리프 노드로 이어지는 트리형 결정 모델 사용

#### 2) Recursive Splitting (재귀적 분할)

- 재귀적 이진 분할을 구현하여 데이터를 대상 변수와 관련하여 최대한 동질적인 하위 집합으로 분할
- 각 노드에서 분할을 반복적으로 수행

#### 3) Stopping Criteria (정지 조건)

- 트리 성장을 제어하는 매개변수 설정
- 주요 매개변수
  - `max_depth` : 트리의 최대 깊이
  - `min_samples_split` : 노드를 분할하기 위해 필요한 최소 샘플 수
  - `min_samples_leaf` : 리프 노드에 필요한 최소 샘플 수
- 트리의 과도한 성장을 방지하여 과적합(Overfitting) 완화

### 차이점

| 구분 | Classification (분류) | Regression (회귀) |
|---|---|---|
| 목적 | 범주형 클래스 예측 | 연속적인 수치 예측 |
| Split 기준 | 하위 노드의 클래스 불순도 감소 | 하위 노드의 MSE 또는 분산 감소 |
| 대표 기준 | Gini Impurity, Entropy | MSE, Variance |
| 목표 | 클래스 레이블이 동일한 하위 그룹 생성 | 정답값이 서로 가까운 하위 그룹 생성 |
| Leaf Node Prediction | 해당 리프 내 다수 클래스 | 해당 리프 내 대상값의 평균 또는 중앙값 |
| Example | 이메일 스팸 구분 | 주택 가격 예측 |

# ML 모델 - Random Forest (랜덤 포레스트)

## 1. Random Forest 개념

- Forest : 숲
- Tree : 나무
- 여러 개의 결정 트리(Decision Tree)가 모여 숲을 이루는 앙상블 모델
- 여러 결정 트리의 예측 결과를 결합하여 최종 예측 수행

### 결정 트리의 단점

- 하나의 결정 트리는 훈련 데이터에 지나치게 맞춰지는 과적합(Overfitting) 경향이 있음
- 데이터의 작은 변화에도 트리 구조가 크게 달라질 수 있음
- 복잡한 트리를 생성할수록 새로운 데이터에 대한 일반화 성능이 저하될 가능성

### Random Forest의 해결 방법

- 여러 개의 결정 트리를 생성하여 개별 트리의 단점을 보완
- 각 트리가 서로 다른 데이터 샘플과 특성을 사용하여 학습
- 여러 트리의 예측 결과를 결합하여 최종 예측값 산출

---

## 2. Random Forest의 학습 과정

※ 예시 : 30개의 Feature를 기반으로 모델을 구성하는 경우

1. 전체 Feature 30개 중 일부 Feature를 무작위로 선택
2. 선택된 Feature와 무작위로 추출된 데이터 샘플을 기반으로 하나의 결정 트리 구성
3. 다른 트리를 구성할 때도 Feature와 데이터 샘플을 서로 다르게 선택
4. 위 과정을 반복하여 여러 개의 결정 트리 생성
5. 각각의 결정 트리가 독립적으로 예측값 산출
6. 여러 결정 트리의 예측값을 결합하여 최종 예측값 결정

### Feature Random Sampling

- 전체 Feature 중 일부를 무작위로 선택하여 각 트리 또는 노드의 분할에 사용
- 트리마다 서로 다른 Feature 조합을 사용하여 트리 간 다양성 확보
- 특정 Feature에 지나치게 의존하는 현상 완화

### Bootstrap Sampling

- 전체 훈련 데이터에서 복원 추출 방식으로 샘플을 선택
- 트리마다 서로 다른 훈련 데이터 구성
- 각 트리가 서로 다른 데이터 패턴을 학습하도록 유도

---

## 3. Random Forest의 예측 방식

### Classification (분류)

- 여러 결정 트리가 각각 클래스를 예측
- 가장 많이 예측된 클래스를 최종 예측값으로 선정
- 다수결 원칙(Majority Voting)

### Regression (회귀)

- 여러 결정 트리가 각각 수치형 예측값 산출
- 개별 트리의 예측값을 모두 더한 후 평균 계산
- 평균값을 최종 예측값으로 선정

### 요약

- 하나의 거대한 결정 트리를 만드는 것이 아니라 여러 개의 결정 트리를 생성
- 여러 트리의 예측 결과를 결합하여 최종 예측 수행
- 분류 : 가장 많이 나온 클래스(다수결)
- 회귀 : 여러 예측값의 평균
- 여러 트리의 결과를 결합하여 개별 트리의 과적합 및 예측 변동성을 완화

# ML 모델 - Appendix - Generalization (일반화)

## 1. Overfitting (과적합)

- 모델이 훈련 데이터에 지나치게 맞춰진 상태
- 훈련 데이터의 노이즈나 세부 패턴까지 학습하여 일반화 능력이 떨어지는 현상
- 훈련 데이터에서는 높은 성능을 보이지만 새로운 데이터에서는 성능이 크게 떨어질 수 있음

## 2. Generalization (일반화)

- 모델이 학습에 사용하지 않은 새로운 데이터에 대해 잘 예측할 수 있는 능력
- 훈련 데이터뿐만 아니라 경험하지 않은 새로운 데이터에서도 높은 성능을 유지할 수 있는지를 나타내는 개념
- 일반화가 잘 된 모델은 새로운 데이터에서도 일관된 성능을 나타냄

## 3. Underfitting (언더피팅)

- 모델이 데이터의 특성과 패턴을 제대로 학습하지 못한 상태
- 모델이 지나치게 단순하거나 학습이 충분하지 않은 경우 발생
- 훈련 데이터와 새로운 데이터 모두에서 성능이 낮게 나타날 수 있음

## 4. Overfitting과 Underfitting 비교

| 구분 | Underfitting | Overfitting |
|---|---|---|
| 학습 상태 | 학습 부족 | 지나치게 학습 |
| 모델 복잡도 | 지나치게 단순 | 지나치게 복잡 |
| 훈련 데이터 성능 | 낮음 | 높음 |
| 새로운 데이터 성능 | 낮음 | 낮음 |
| 원인 | 데이터 패턴을 충분히 학습하지 못함 | 훈련 데이터의 노이즈 및 세부 패턴까지 학습 |
| 해결 방법 | 모델 복잡도 증가, 학습 개선 | 모델 복잡도 감소, 정규화, 데이터 증가 등 |

# ML 모델 - Model Evaluation (모델 평가)

## 1. Confusion Matrix (혼동 행렬)

- 분류 모델의 예측 결과와 실제 정답을 비교하여 모델의 성능을 평가하는 표

| 구분 | 의미 |
|---|---|
| TP (True Positive) | 실제 Positive인 데이터를 Positive로 예측 |
| TN (True Negative) | 실제 Negative인 데이터를 Negative로 예측 |
| FP (False Positive) | 실제 Negative인 데이터를 Positive로 잘못 예측 |
| FN (False Negative) | 실제 Positive인 데이터를 Negative로 잘못 예측 |

※ FP와 FN의 설명을 주의해야 함

- FP : 실제 Negative인데 Positive로 예측한 경우
- FN : 실제 Positive인데 Negative로 예측한 경우

---

## 2. Classification Performance Metrics (분류 성능 평가 지표)

### 1) Accuracy (정확도)

- 전체 예측 중 올바르게 예측한 비율
- 전체 데이터 중 모델이 정답을 맞힌 비율

Accuracy = (TP + TN) / (TP + TN + FP + FN)

### 2) Precision (정밀도)

- Positive로 예측한 데이터 중 실제 Positive인 비율
- 모델이 Positive라고 예측했을 때 실제로 맞을 확률

Precision = TP / (TP + FP)

### 3) Sensitivity / Recall (민감도 / 재현율)

- 실제 Positive 데이터를 얼마나 잘 예측했는지를 나타내는 지표
- 실제 Positive 전체 중 모델이 올바르게 Positive로 예측한 비율

Recall = TP / (TP + FN)

### 4) Specificity (특이도)

- 실제 Negative 데이터를 얼마나 잘 예측했는지를 나타내는 지표
- 실제 Negative 전체 중 모델이 올바르게 Negative로 예측한 비율

Specificity = TN / (TN + FP)

### 5) F1 Score (F1 점수)

- Precision과 Recall의 조화평균
- Precision과 Recall 중 낮은 값에 상대적으로 더 큰 영향을 받음
- 클래스 불균형 데이터에서 Accuracy만으로 성능을 평가하기 어려운 경우 활용
- False Positive와 False Negative의 중요성을 함께 고려해야 하는 경우 사용

F1 Score = 2 × (Precision × Recall) / (Precision + Recall)

#### F1 Score가 1에 가까운 경우

- Precision과 Recall이 모두 높음
- Positive로 예측한 결과의 정확도가 높음
- 실제 Positive 사례를 대부분 올바르게 감지

#### F1 Score가 낮은 경우

- Precision 또는 Recall 중 하나 이상이 낮음
- Positive 예측의 정확도가 낮거나 실제 Positive 사례를 많이 놓치는 상태

---

## 3. 클래스 비대칭 데이터 처리 (Class Imbalance)

### 1) 클래스 간 비대칭

- 데이터 세트 내에서 한 클래스의 샘플 수가 다른 클래스에 비해 현저히 많거나 적은 경우
- 클래스 불균형(Class Imbalance)이라고도 함
- 모델이 다수 클래스에 치우쳐 학습하는 경향을 가지게 만들어 소수 클래스의 예측 성능이 저하될 수 있음

### 2) 데이터 레벨 접근 방법

#### Oversampling (오버샘플링)

- 소수 클래스의 샘플 수를 증가시켜 데이터 세트의 균형을 맞추는 방법
- 기존 소수 클래스 데이터를 반복적으로 복제하거나 새로운 샘플을 생성
- SMOTE 등의 기법을 사용하여 소수 클래스의 샘플을 합성적으로 생성

#### Undersampling (언더샘플링)

- 다수 클래스의 샘플 수를 줄여 데이터 세트의 균형을 맞추는 방법
- 다수 클래스의 데이터를 일부 제거
- 데이터 손실로 인해 유용한 정보가 사라질 수 있으므로 주의 필요

### 3) 알고리즘 레벨 접근 방법

#### Class Weight (가중치 부여)

- 소수 클래스의 샘플에 더 높은 가중치를 부여
- 모델 학습 과정에서 소수 클래스의 오분류가 더 큰 영향을 미치도록 설정
- 소수 클래스의 예측 성능 향상을 유도

#### Ensemble Method (앙상블 기법)

- 여러 모델의 예측 결과를 결합하는 방법
- 모델의 다양성을 활용하여 소수 클래스에 대한 예측 성능 향상을 유도
- Balanced Random Forest 등의 기법 활용 가능

### 4) 평가 지표 선택

- 클래스 불균형 데이터에서는 Accuracy만으로 모델 성능을 평가하기 어려움
- Precision, Recall, F1 Score 등의 지표를 함께 사용
- 소수 클래스의 특성과 문제의 목적에 따라 적절한 평가 지표 선택

### 5) 기타 방법

#### Feature Selection (특징 선택)

- 소수 클래스를 더 잘 구별할 수 있는 유의미한 Feature를 선택
- 불필요한 Feature를 제거하여 모델의 성능과 해석력을 향상

# ML 모델 - Model Evaluation & Management

## 1. 모델 평가 기록 및 관리 솔루션

### Experiment Tracking (실험 기록 및 비교)

- 모델 학습 과정의 설정값, 성능 지표, 실험 결과 등을 기록하고 비교
- 여러 실험의 결과를 추적하고 관리
- 주요 도구
  - MLflow
  - Weights & Biases (W&B)

### Model Version Management (모델 버전 관리)

- 학습된 모델의 버전을 관리
- 모델의 학습 조건, 성능, 파일 등을 기록
- 이전 모델과 새로운 모델을 비교하고 배포할 모델을 관리
- 주요 도구
  - MLflow Model Registry
  - Amazon SageMaker Model Registry

### Feature Management (피처 관리)

- 모델 학습과 예측에 사용되는 Feature를 저장, 관리 및 제공
- 학습 환경과 실제 서비스 환경에서 동일한 Feature를 사용할 수 있도록 관리
- 주요 도구
  - Feature Store
  - Feast
  - Tecton

# 1. 데이터 사이언스(Data Science)란?

## 1-1. 데이터 사이언스의 정의 (개인의 의견)

데이터 사이언스란 **데이터의 의미를 도출하여 문제의 해결 방안을 찾고, 해결 방법을 실행하는 것**이라고 생각한다.

현재 공공기관, 교육기관, 법무기관 등 다양한 기관에서 데이터의 중요도가 상승하고 있다.

또한 AI의 발전으로 데이터 분석 및 활용의 진입장벽이 낮아지면서 데이터 활용자가 증가하고 있다.

이에 따라 AI 기술과 데이터 관리의 중요성도 함께 상승하고 있다.

## 1-2. 바이브 코딩(Vibe Coding)

**정의**

개발자가 직접 코드를 작성하는 대신, 일상적인 언어로 아이디어나 요구사항을 설명하면 AI가 실행 가능한 코드를 자동으로 생성하거나 수정해 주는 개발 방식이다.

## 1-3. 바이브 코딩 시대 개발자의 경쟁력

AI가 코드를 작성할 수 있는 시대에는 단순히 코드를 작성하는 능력보다 다음과 같은 역량이 중요하다.

1. 학습 가능한 문제로의 정의
2. 문제 해결을 위한 데이터화
3. 적절한 모델 설계

즉, 해결해야 할 문제를 명확하게 정의하고, 이를 데이터로 표현하며, 적합한 모델을 설계하는 능력이 중요하다.

## 1-4. 데이터 사이언스(DS)의 업무 과정

| 순서 | 업무 과정 | 주요 내용 |
|---|---|---|
| 1 | 문제 정의 | 해결해야 할 문제와 목표 설정 |
| 2 | 데이터 수집 및 전처리 | 데이터 확보, 오류 및 결측치 처리 |
| 3 | 탐색적 분석 및 통계 | 데이터의 특성, 패턴, 관계 분석 |
| 4 | 모델 개발 | 문제에 적합한 분석 및 예측 모델 개발 |
| 5 | 모델 평가 및 개선 | 모델 성능 평가 및 개선 |
| 6 | 결과 해석 및 서비스 적용 | 분석 결과 해석 및 실제 서비스에 적용 |

**※ 모델 설계 시 중요 사항**

- 베이스라인(Baseline) 모델을 설정한다.
- 베이스라인 모델은 성능을 비교하기 위한 기준 모델이다.
- 새로운 모델을 개발할 때는 베이스라인 모델보다 성능이 개선되었는지 확인해야 한다.

# 2. 데이터(Data), 정보(Information), 지식(Knowledge)

데이터는 정보가 되고, 정보는 지식으로 발전할 수 있다.

| 구분 | 정의 | 핵심 의미 |
|---|---|---|
| 데이터(Data) | 관찰된 값이나 사실 자체를 일차적으로 표현한 것 | 최초의 관찰 및 측정값 |
| 정보(Information) | 데이터에 구조와 의미를 부여하여 사용자에게 유용한 형태로 변환한 것 | 데이터의 해석 |
| 지식(Knowledge) | 정보를 바탕으로 이해, 경험, 학습 등을 통해 축적된 통찰이나 원칙 | 해석된 정보에 도메인 지식을 적용한 것 |

## 2-1. 데이터(Data)

- 관찰된 값이나 사실 자체에 대한 일차적인 표현
- 관찰이나 측정을 통해 최초로 확인되는 정보

## 2-2. 정보(Information)

- 관련성과 목적을 갖춘 데이터
- 데이터에 구조와 의미를 부여하여 사용자에게 유용한 형태로 변환한 결과
- 데이터를 해석하여 의미를 부여한 것

## 2-3. 지식(Knowledge)

- 정보를 바탕으로 이해, 경험, 학습 등을 통해 축적된 통찰이나 원칙
- 특정 문제를 해결하거나 의사결정을 내리는 데 사용할 수 있는 심층적인 이해
- 해석된 데이터에 개인의 경험과 도메인 지식을 적용하여 활용하는 것

### 데이터 → 정보 → 지식의 관계

```text
데이터(Data)
    │
    │ 구조와 의미 부여
    ▼
정보(Information)
    │
    │ 경험, 이해, 학습 및 해석
    ▼
지식(Knowledge)
    │
    │ 문제 해결 및 의사결정
    ▼
실제 활용
```

# 3. 데이터 리터러시(Data Literacy)

## 3-1. 데이터 리터러시의 정의

데이터를 읽고, 이해하고, 올바르게 해석하여 의사소통과 의사결정에 활용하는 능력이다.

즉, **데이터를 보고 그 의미를 이해하는 문해력**이라고 할 수 있다.

현대의 문해력은 단순히 글자를 읽고 이해하는 수준을 넘어섰다.

디지털 기기와 영상, 이미지 등의 정보를 해석하는 미디어 리터러시(Media Literacy) 및 디지털 문해력(Digital Literacy)으로 개념이 확장되고 있다.

## 3-2. 데이터 리터러시의 구성 요소

데이터 리터러시는 크게 4가지 요소로 구분할 수 있다.

| 구성 요소 | 정의 | 주요 역할 |
|---|---|---|
| 데이터 읽기 | 숫자, 표, 그래프에 담긴 정보를 읽고 데이터의 의미와 구조를 파악하는 능력 | 데이터 이해 |
| 데이터 분석 | 데이터를 정리하고 비교하여 차이, 변화, 패턴 및 관계를 파악하는 능력 | 문제 원인 분석 |
| 데이터 활용 | 분석 결과를 실제 문제 해결이나 의사결정에 적용하는 능력 | 실제 행동 및 대응 |
| 커뮤니케이션 | 데이터에서 발견한 내용과 의미를 상대방이 이해할 수 있도록 설명하는 능력 | 분석 결과 전달 |

## 3-3. 데이터 읽기(Data Reading)

**정의**

숫자, 표, 그래프에 담긴 정보를 읽고 데이터의 의미와 구조를 파악하는 능력이다.

**중요 사항**

- 단순히 숫자를 읽는 것과 숫자의 의미를 이해하는 것은 다르다.
- 데이터의 기준, 단위, 맥락을 함께 이해해야 한다.

예시:

```text
매출액: 1억 원
```

단순히 1억 원이라는 숫자를 확인하는 것만으로는 충분하지 않다.

- 어떤 기간의 매출인가?
- 전월 대비 증가한 것인가, 감소한 것인가?
- 매출을 계산한 기준은 무엇인가?

숫자의 기준과 맥락을 함께 파악해야 의미를 이해할 수 있다.

## 3-4. 데이터 분석(Data Analysis)

**정의**

데이터를 정리하고 비교하여 차이, 변화, 패턴 및 관계를 파악하는 능력이다.

**예시: 매출 감소 원인 분석**

매출이 감소했다는 문제를 발견했을 때 다음과 같이 세부 원인을 분석할 수 있다.

```text
매출 감소
   │
   ├── 방문자 수 감소
   │
   ├── 방문자 중 구매한 사람의 비율 감소
   │
   └── 구매 1건당 결제 금액 감소
```

단순히 매출이 감소했다는 사실을 확인하는 데 그치지 않고, 매출 감소의 원인이 무엇인지 찾아내는 과정이다.

## 3-5. 데이터 활용(Data Utilization)

**정의**

데이터 분석 결과를 실제 문제 해결이나 의사결정에 적용하는 능력이다.

주요 내용:

- 분석을 통해 얻은 정보를 구체적인 행동으로 연결한다.
- 분석 결과에 따라 개선 방안을 실행한다.
- 실행한 행동의 효과를 다시 데이터로 확인한다.

즉, 분석 결과를 실제 행동으로 연결하고 그 결과까지 확인하는 과정이다.

## 3-6. 커뮤니케이션(Communication)

**정의**

데이터에서 발견한 내용과 그 의미를 상대방이 이해할 수 있도록 설명하는 능력이다.

주요 내용:

- 목적에 맞는 표와 그래프를 선택한다.
- 분석 근거와 해석을 구분한다.
- 분석 결과를 바탕으로 제안 사항을 전달한다.
- 상대방이 이해할 수 있는 언어를 사용한다.

### 예시: 매출 분석 보고

| 구분 | 내용 |
|---|---|
| 문제 | 매출 감소 |
| 확인한 사실 | 모바일 방문자의 구매 비율이 낮아짐 |
| 해석과 한계 | 구매 과정의 불편이 원인일 가능성이 있으나 아직 확인되지 않음 |
| 제안 | 구매 과정 점검 및 개선안 비교 실험 |

**핵심**

분석한 데이터를 단순히 전달하는 것이 아니라, 읽는 사람이 내용을 이해하고 의사결정에 활용할 수 있도록 설명해야 한다.

## 3-7. 데이터 리터러시 최종 정리

| 구분 | 핵심 역량 |
|---|---|
| 읽기 | 측정값, 단위, 기준의 의미를 이해 |
| 분석 | 변화량과 추세를 확인하고 예측의 가정을 검토 |
| 활용 | 분석 결과를 실제 대응 및 의사결정에 반영 |
| 소통 | 상황, 예상 위험, 불확실성 및 필요한 대응 전달 |

# 4. 데이터의 분류(Data Classification)

데이터는 변수의 유형과 데이터의 구조에 따라 분류할 수 있다.

## 4-1. 변수 유형에 따른 분류

변수(Variable)는 관찰 대상의 특성이나 속성을 나타내는 값이다.

변수 유형은 크게 범주형과 수치형으로 구분할 수 있다.

```text
변수 유형
   │
   ├── 범주형(Categorical)
   │      │
   │      ├── 명목형(Nominal)
   │      │
   │      └── 순서형(Ordinal)
   │
   └── 수치형(Numerical)
          │
          ├── 이산형(Discrete)
          │
          └── 연속형(Continuous)
```

### ① 범주형 데이터(Categorical Data)

범주형 데이터는 데이터를 특정한 범주나 그룹으로 구분하는 자료이다.

일반적으로 질적 데이터(Qualitative Data)라고도 한다.

| 구분 | 영문 | 정의 | 예시 |
|---|---|---|---|
| 명목형 | Nominal | 순서나 크기의 의미 없이 범주로 구분되는 데이터 | 성별, 혈액형 |
| 순서형 | Ordinal | 범주 사이에 순서 관계가 존재하는 데이터 | 만족도, 성적 등급 |

**명목형(Nominal)**

- 데이터를 특정 그룹으로 분류한다.
- 범주 사이에 순서나 크기의 의미가 없다.
- 예: 혈액형(A형, B형, O형, AB형)

**순서형(Ordinal)**

- 데이터를 특정 그룹으로 분류한다.
- 범주 사이에 순서 관계가 존재한다.
- 다만 각 단계 사이의 간격이 동일하다고 볼 수는 없다.
- 예: 만족도(매우 불만족, 불만족, 보통, 만족, 매우 만족)

### ② 수치형 데이터(Numerical Data)

수치형 데이터는 숫자로 표현되며 수량이나 크기를 나타내는 자료이다.

일반적으로 양적 데이터(Quantitative Data)라고도 한다.

| 구분 | 영문 | 정의 | 예시 |
|---|---|---|---|
| 이산형 | Discrete | 셀 수 있는 개별적인 값을 갖는 데이터 | 인원 수, 방문 횟수 |
| 연속형 | Continuous | 일정한 범위 내에서 연속적인 측정값을 갖는 데이터 | 신장, 체중, 온도 |

**이산형(Discrete)**

- 값이 연속적이지 않고 개별적으로 구분된다.
- 일반적으로 정수 단위로 셀 수 있는 값이다.
- 예: 학생 수, 방문자 수, 제품 수

어원 참고:

- 이산(離散): 떨어질 이(離), 흩어질 산(散)
- 서로 떨어져 개별적으로 구분되는 형태를 의미한다.

**연속형(Continuous)**

- 일정한 범위 내에서 연속적인 값을 가질 수 있다.
- 측정 정밀도에 따라 소수점 이하의 값도 표현할 수 있다.
- 예: 신장, 체중, 시간, 온도

**※ 이산형과 연속형의 차이**

| 비교 기준 | 이산형 | 연속형 |
|---|---|---|
| 값의 형태 | 개별적으로 구분되는 값 | 연속적으로 측정되는 값 |
| 측정 방식 | 개수 계산 | 측정 |
| 소수점 | 일반적으로 사용하지 않음 | 사용할 수 있음 |
| 예시 | 인원 수, 방문 횟수 | 키, 몸무게 |

## 4-2. 데이터 구조에 따른 분류

데이터는 구조화된 정도에 따라 정형, 반정형, 비정형 데이터로 구분할 수 있다.

| 구분 | 영문 | 정의 | 예시 |
|---|---|---|---|
| 정형 데이터 | Structured Data | 정해진 형식과 구조에 따라 체계적으로 구성된 데이터 | 관계형 데이터베이스, 엑셀 표 |
| 반정형 데이터 | Semi-structured Data | 일정한 구조적 규칙이나 메타데이터를 가지지만 고정된 표 구조는 아닌 데이터 | JSON, XML, 로그 |
| 비정형 데이터 | Unstructured Data | 고정된 데이터 구조나 형식이 없는 데이터 | 영상, 음성, 텍스트, 이미지 |

### ① 정형 데이터(Structured Data)

- 행과 열로 구성된 표 형태의 데이터
- 정해진 스키마와 구조를 가진다.
- 데이터베이스나 엑셀에서 자주 사용한다.

### ② 반정형 데이터(Semi-structured Data)

- 완전히 정형화된 표 형태는 아니다.
- 태그, 키-값, 메타데이터 등을 통해 일정한 구조를 가진다.
- 예: JSON, XML, 로그 데이터

### ③ 비정형 데이터(Unstructured Data)

- 정해진 행과 열의 구조가 없다.
- 텍스트, 이미지, 음성, 영상 등 다양한 형태로 구성된다.
- 별도의 처리 및 분석 기술이 필요할 수 있다.

### 데이터 구조 유형 정리

```text
데이터 구조
   │
   ├── 정형 데이터
   │      └── 표, 관계형 데이터베이스
   │
   ├── 반정형 데이터
   │      └── JSON, XML, 로그
   │
   └── 비정형 데이터
          └── 이미지, 영상, 음성, 텍스트
```

**※ 시퀀스 데이터(Sequence Data)**

- 순서에 따라 배열된 데이터이다.
- 시간, 발생 순서, 위치 등의 순서 정보가 중요하다.
- 예: 주식 가격의 시간별 변화, 사용자 행동 기록, 문장 속 단어의 순서

시퀀스 데이터가 반드시 정형 데이터인 것은 아니다. 데이터의 구조와 표현 방식에 따라 정형 또는 비정형 등으로 구분될 수 있다.

# 5. 기술통계와 추론통계

통계학은 데이터를 요약하고 분석하거나 모집단의 특성을 추정하는 데 활용된다.

## 5-1. 기술통계(Descriptive Statistics)

**정의**

수집한 데이터를 요약하고 정리하여 데이터의 특성을 파악하는 통계 방법이다.

주요 내용:

- 평균
- 중앙값
- 최빈값
- 분산
- 표준편차
- 데이터 분포
- 데이터 시각화

핵심 목적:

수집한 데이터가 어떤 특성을 가지고 있는지 이해하기 쉽게 요약하고 표현하는 것이다.

## 5-2. 추론통계(Inferential Statistics)

**정의**

표본 데이터를 분석하여 모집단의 특성을 추정하거나 가설을 검정하는 통계 방법이다.

주요 내용:

- 모집단 추정
- 모수 추정
- 신뢰구간
- 가설 검정
- 통계적 유의성

핵심 목적:

모집단 전체를 조사하지 않고 표본을 통해 모집단의 특성을 추론하는 것이다.

## 5-3. 기술통계와 추론통계 비교

| 구분 | 기술통계 | 추론통계 |
|---|---|---|
| 영문 | Descriptive Statistics | Inferential Statistics |
| 목적 | 데이터 요약 및 정리 | 모집단 특성 추정 및 가설 검정 |
| 주요 방법 | 평균, 분산, 표준편차, 시각화 | 추정, 신뢰구간, 가설 검정 |
| 활용 | 수집된 데이터의 특성 파악 | 모집단에 대한 의사결정 |

# 6. 모집단과 표본

## 6-1. 모집단(Population)

연구에서 관심을 가지고 조사하려는 전체 집단이다.

예시:

- 특정 학교의 전체 학생
- 특정 기업의 전체 직원
- 대한민국 전체 국민

## 6-2. 표본(Sample)

모집단에서 추출한 일부 집합이다.

예시:

- 특정 학교 전체 학생 중 100명
- 특정 기업 전체 직원 중 50명
- 대한민국 국민 중 무작위로 선정한 1,000명

## 6-3. 모집단과 표본의 관계

```text
모집단(Population)
 ├── 표본 1
 ├── 표본 2
 ├── 표본 3
 └── ...
 
표본을 분석하여 모집단의 특성을 추정
```

| 구분 | 모집단 | 표본 |
|---|---|---|
| 의미 | 연구 대상 전체 | 모집단에서 추출한 일부 |
| 범위 | 전체 집단 | 일부 집단 |
| 목적 | 전체 특성 파악 | 모집단 특성 추정 |
| 예시 | 전체 학생 | 학생 중 선정된 100명 |

## 6-4. 추가 학습 질문

**빅데이터 시대에도 표본을 사용하는 통계가 의미가 있는가?**

생각해 볼 사항:

- 빅데이터가 존재한다면 전체 데이터를 분석하는 것이 더 정확한가?
- 데이터가 많더라도 표본 추출이 필요한 상황은 무엇인가?
- 데이터의 양과 데이터의 대표성은 어떤 관계가 있는가?
- 전체 데이터를 수집하더라도 편향이나 측정 오류가 발생할 수 있는가?
- 모집단 전체를 조사하는 전수조사와 표본조사의 장단점은 무엇인가?
